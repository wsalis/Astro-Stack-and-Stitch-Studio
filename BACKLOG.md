## Next-Version Parking Lot

- [ ] **Camera-aware mixed-model quality and calibration.** Keep good frames from different Seestar models in one master while evaluating each frame fairly across sensor differences. Current batch grouping produces separate masters; that is not a substitute for mixed-model quality handling.
	- Implemented conservatively (2026-10-23): default-on, metadata-gated prefilters use setup/exposure star-count and sky baselines plus session-wide angular FWHM. Homogeneous/incomplete-metadata inputs keep legacy decisions; GUI/CLI opt-out, sparse-cohort handling, setup logs and camera/scale/angular-FWHM report fields are covered by regression tests, including homogeneous end-to-end output parity. This does not change late transparency/PSFSW filters, reference choice, weights, normalization or calibration. Real mixed-model validation, metadata overrides and remaining items below are still open.
	- Identify camera model from reliable FITS metadata, with an explicit user override when headers are missing or inconsistent. Preserve unknown identity rather than guessing.
	- Normalize sharpness comparisons by angular pixel scale where metadata permits; establish star-count and sky baselines within model/exposure cohorts so resolution and sensitivity differences do not skew rejection.
	- Review weighting across models so raw signal scale or sensor gain does not systematically favor one camera. Consider selecting calibration masters per camera when dimensions/sensor characteristics differ.
	- Do not let a uniformly poor model cohort pass solely because it is internally consistent; combine within-cohort outlier checks with an explicit global quality floor or user-controlled thresholds.
	- Report model identity, normalized sharpness, weight, and rejection reason per frame; leave unsupported comparisons explicit.
	- Acceptance: mixed-model tests and a representative real dataset show that a good S50 standard frame remains eligible, a genuinely poor S50 Pro frame is rejected or strongly down-weighted, and the retained cameras still produce one master without a measurable regression in the shared field.
- [ ] **Explore creative and alternative weighting methods.** Research alternatives to the current scalar frame weights and compare their image-quality tradeoffs before changing defaults. Examples to investigate, not decisions:
	- Multi-metric quality scores using robust ranks or a Pareto frontier across noise, transparency, sharpness, and star quality, rather than multiplying metrics that may be correlated.
	- Spatially adaptive weights that combine local PSF quality, noise, and transparency, with confidence limits where a region has too few stars or too little coverage.
	- Per-pixel uncertainty weighting from signal-dependent shot noise and read noise, bounded by empirical noise estimates so uncertain calibration metadata cannot dominate.
	- Goal-oriented profiles such as maximum depth, balanced, and sharper stars, while reporting the depth/sharpness tradeoff instead of implying one weighting is universally best.
	- Acceptance: benchmark each candidate against current methods on representative big-rig and Seestar data using star SNR/count, PSF width, nebula SNR, rejection behavior, and effective frame count. Keep current defaults unless a candidate produces a repeatable, understood improvement; preserve side-by-side output comparison.
- [ ] **Registration confidence gate and diagnostics.** Quantify whether each frame's alignment is trustworthy before it contributes to the stack; prefer explainable warnings and opt-in rejection thresholds until validated.
	- Record matched/inlier counts, residual RMS and distribution, transform scale/rotation, and estimated overlap/coverage; flag implausible transforms or low-confidence fits with per-frame reasons.
	- Test synthetic shifts, rotations, scale changes, flips, distortion, sparse/crowded fields, and deliberately incorrect matches. Avoid rejecting valid frames solely because their field differs or has fewer stars.
	- Acceptance: bad registrations are reliably caught before contaminating the stack, valid difficult frames remain usable, and default behavior is unchanged until real-data benchmarks establish safe thresholds.
- [ ] **Motion and trailing quality checks.** Detect tracking/wind blur that star count and scalar FWHM may miss, without confusing real sensor-field patterns or optical distortion for motion.

	- Write checkpoints atomically (temporary artifact then commit marker/rename); treat partial writes as incomplete. Never infer completion only from file existence.
	- Make checkpoint retention/cleanup explicit. A successful run may clean temporary checkpoints according to the chosen setting; failed/interrupted runs must preserve valid checkpoints for recovery.
	- Verified 2026-10-15: full suite passes (186 tests); tests cover resume from registered, global, local-normalization, and master checkpoints, plus cancellation at the stack boundary and master-payload corruption.
